<section class="home-section" aria-labelledby="home-why">
<p class="home-eyebrow">Why VitePress Sidebar</p>
<h2 id="home-why">Your sidebar, generated from your files</h2>
<p class="home-lead">The VitePress sidebar lists exactly what <code>themeConfig.sidebar</code> tells it to, and that list is written by hand. Every page you add, rename, or move means another edit to the config, and a missed edit shows up as a missing or broken menu item.</p>
<p class="home-lead">VitePress Sidebar reads your documentation folder instead. It walks the folders and Markdown files under the path you choose, takes each menu title from the page itself, filters and sorts the entries by your rules, and hands VitePress a sidebar in the exact format it expects. Your folder structure decides the navigation, and the config stays short.</p>
</section>

<section class="home-section" aria-labelledby="home-features">
<p class="home-eyebrow">Features</p>
<h2 id="home-features">Everything a documentation sidebar needs</h2>
<p class="home-lead">Nearly 50 options cover titles, links, ordering, filtering, and grouping. Here is what they add up to.</p>
<ul class="home-feature-list">
<li><h3>Built from your folders</h3><p>Every folder becomes a group and every Markdown file becomes a link, following the tree on disk.</p></li>
<li><h3>Titles from your pages</h3><p>Read menu titles from the first <code>h1</code>, a frontmatter field, or the <code>index.md</code> of a folder.</p></li>
<li><h3>Flexible sorting</h3><p>Sort by name, frontmatter <code>order</code>, date, a number in the title, or a compare function of your own.</p></li>
<li><h3>Include and exclude</h3><p>Hide pages with glob patterns, a frontmatter flag, or a folder depth. The <code>srcExclude</code> of VitePress is applied as well.</p></li>
<li><h3>Collapsible groups</h3><p>Choose whether groups can collapse, and from which depth or level they start closed.</p></li>
<li><h3>Multiple sidebars</h3><p>Show a different sidebar under each path, such as <code>/guide/</code> and <code>/api/</code>.</p></li>
<li><h3>Internationalization</h3><p>Build one sidebar per language directory to match the <code>locales</code> of VitePress.</p></li>
<li><h3>Per-folder configuration</h3><p>Put a <code>sidebar.config.json</code> in any folder to set the options of that part of the tree.</p></li>
<li><h3>Dynamic routes</h3><p>List the pages a <code>[param].md</code> template generates instead of the template itself.</p></li>
<li><h3>Title formatting</h3><p>Turn hyphens and underscores into spaces, capitalize words, and strip number prefixes such as <code>1.</code> from titles.</p></li>
<li><h3>Refresh in development</h3><p>With <code>withSidebar</code>, adding or removing a page refreshes the sidebar without restarting the dev server.</p></li>
<li><h3>TypeScript types</h3><p>Every option is typed, and the types can be imported from <code>vitepress-sidebar/types</code>.</p></li>
</ul>
</section>

<section class="home-section" aria-labelledby="home-use-cases">
<p class="home-eyebrow">Use cases</p>
<h2 id="home-use-cases">Made for real documentation sites</h2>
<p class="home-lead">Product manuals, multilingual sites, blogs, and generated reference pages all run on the same plugin, each with a few options.</p>
<div class="home-usecases">
<article class="home-usecase">
<h3>A separate sidebar for each section</h3>
<p>Give <code>/guide/</code> and <code>/api/</code> a sidebar of their own, so readers only see the menu of the section they are in.</p>

```js
withSidebar(vitePressOptions, [
  {
    documentRootPath: '/docs',
    scanStartPath: 'guide',
    resolvePath: '/guide/'
  },
  {
    documentRootPath: '/docs',
    scanStartPath: 'api',
    resolvePath: '/api/'
  }
]);
```

[Read the multiple sidebars guide](/advanced-usage/multiple-sidebars-how-to)

</article>
<article class="home-usecase">
<h3>Documentation in several languages</h3>
<p>Generate one sidebar per language directory. Each translation gets a menu built from its own files and its own headings.</p>

```js
withSidebar(
  vitePressOptions,
  ['en', 'ko'].map((lang) => ({
    documentRootPath: `/docs/${lang}`,
    resolvePath: `/${lang}/`,
    useTitleFromFileHeading: true
  }))
);
```

[Read the internationalization guide](/advanced-usage/internationalization)

</article>
<article class="home-usecase">
<h3>A blog or release notes, newest first</h3>
<p>Give each post a <code>date</code> in its frontmatter. The newest post stays at the top of the menu as you publish, with no list to maintain.</p>

```js
const sidebarOptions = {
  sortMenusByFrontmatterDate: true,
  sortMenusOrderByDescending: true
};
```

[See every sorting option](/guide/options#sortmenusbyfrontmatterdate)

</article>
<article class="home-usecase">
<h3>Different rules for each part of the tree</h3>
<p>A <code>sidebar.config.json</code> configures its folder and everything below it. Its <code>$folder</code> key names and links the folder itself, even without an <code>index.md</code>.</p>

```json
// docs/api/sidebar.config.json
{
  "collapsed": true,
  "$folder": {
    "text": "API Reference",
    "link": "/api/overview"
  }
}
```

[Read the configuration file guide](/advanced-usage/configuration-file)

</article>
<article class="home-usecase">
<h3>Drafts that stay out of the menu</h3>
<p>Mark an unfinished page with <code>draft: true</code> in its frontmatter and it is left out of the sidebar. Pages excluded by <code>srcExclude</code> are left out as well.</p>

```js
const sidebarOptions = {
  excludeFilesByFrontmatterFieldName: 'draft'
};
```

[See every exclusion option](/guide/options#excludefilesbyfrontmatterfieldname)

</article>
<article class="home-usecase">
<h3>Pages generated by dynamic routes</h3>
<p>A <code>[pkg].md</code> template and its <code>paths</code> loader appear as the pages they generate, one menu item per package, instead of as a template that links nowhere.</p>

```js
const sidebarOptions = {
  includeDynamicRoutes: true,
  useTitleFromFileHeading: true
};
```

[Read about dynamic routes](/guide/options#includedynamicroutes)

</article>

<h3>Wrap your VitePress config</h3>
<p>Pass your existing options to <code>withSidebar</code> together with the folder that holds your documents.</p>
</div>
<div class="home-step-code">

```js
// docs/.vitepress/config.js
import { defineConfig } from 'vitepress';
import { withSidebar } from 'vitepress-sidebar';

const vitePressOptions = {
  title: 'My Docs'
};

export default defineConfig(
  withSidebar(vitePressOptions, {
    documentRootPath: '/docs'
  })
);
```

<h2 id="home-faq">Frequently asked questions</h2>
<div class="home-faq">
<div class="home-faq-item">
<h3>Does it replace a sidebar I already wrote?</h3>

Yes. `withSidebar` replaces `themeConfig.sidebar` with the generated sidebar. When some pages must stay in a fixed order, list them in [`manualSortFileNameByPriority`](/guide/options#manualsortfilenamebypriority) or give them an `order` in their frontmatter instead of keeping a handwritten list.

</div>
<div class="home-faq-item">
<h3>How do I control the order of the menu?</h3>

Files and folders are sorted by name by default. You can put chosen names first, sort by the frontmatter `order` or `date`, sort by the numbers in titles or links, or decide every comparison yourself with [`sortMenusByCustomFunction`](/guide/options#sortmenusbycustomfunction).

</div>
<div class="home-faq-item">
<h3>Does the sidebar update while the dev server is running?</h3>

With `withSidebar`, adding or removing a Markdown file, or editing a `sidebar.config.json`, refreshes the sidebar without a manual restart. With `generateSidebar`, the dev server has to be restarted.

</div>
<div class="home-faq-item">
<h3>Can I use it in a CommonJS project?</h3>

The package is published as an ES module. Rename the VitePress config file to `.mjs`, or add `"type": "module"` to `package.json`. The [troubleshooting page](/troubleshooting/err-require-esm) walks through both.

</div>
<div class="home-faq-item">
<h3>What does it require?</h3>

Node.js 20 or later, with Node.js 22 recommended, and a VitePress project. The [getting started guide](/guide/getting-started) covers the installation.

</div>
<div class="home-faq-item">
<h3>Is it free to use?</h3>

Yes. VitePress Sidebar is open source under the MIT License, including in commercial projects. The source code and the issue tracker are on [GitHub](https://github.com/jooy2/vitepress-sidebar).
