Why VitePress Sidebar

Your sidebar, generated from your files

The VitePress sidebar lists exactly what themeConfig.sidebar tells it to, and that list is written by hand. Every page you add, rename, or move means another edit to the config, and a missed edit shows up as a missing or broken menu item.

VitePress Sidebar reads your documentation folder instead. It walks the folders and Markdown files under the path you choose, takes each menu title from the page itself, filters and sorts the entries by your rules, and hands VitePress a sidebar in the exact format it expects. Your folder structure decides the navigation, and the config stays short.

Features

Everything a documentation sidebar needs

Nearly 50 options cover titles, links, ordering, filtering, and grouping. Here is what they add up to.

  • Built from your folders

    Every folder becomes a group and every Markdown file becomes a link, following the tree on disk.

  • Titles from your pages

    Read menu titles from the first h1, a frontmatter field, or the index.md of a folder.

  • Flexible sorting

    Sort by name, frontmatter order, date, a number in the title, or a compare function of your own.

  • Include and exclude

    Hide pages with glob patterns, a frontmatter flag, or a folder depth. The srcExclude of VitePress is applied as well.

  • Collapsible groups

    Choose whether groups can collapse, and from which depth or level they start closed.

  • Multiple sidebars

    Show a different sidebar under each path, such as /guide/ and /api/.

  • Internationalization

    Build one sidebar per language directory to match the locales of VitePress.

  • Per-folder configuration

    Put a sidebar.config.json in any folder to set the options of that part of the tree.

  • Dynamic routes

    List the pages a [param].md template generates instead of the template itself.

  • Title formatting

    Turn hyphens and underscores into spaces, capitalize words, and strip number prefixes such as 1. from titles.

  • Refresh in development

    With withSidebar, adding or removing a page refreshes the sidebar without restarting the dev server.

  • TypeScript types

    Every option is typed, and the types can be imported from vitepress-sidebar/types.

Example

From a folder to a sidebar

A small documentation site, the only sidebar setup it needs, and the sidebar VitePress Sidebar generated from it. The result below was produced by running this exact configuration.

1Your files

text
docs/
├─ .vitepress/
│  └─ config.js
├─ index.md
├─ introduction.md
├─ guide/
│  ├─ index.md
│  ├─ 1.installation.md
│  ├─ 2.configuration.md
│  └─ 3.deployment.md
└─ api/
   ├─ index.md
   ├─ client-methods.md
   └─ server-hooks.md

2Your config

js
// docs/.vitepress/config.js
import { defineConfig } from 'vitepress';
import { withSidebar } from 'vitepress-sidebar';

export default defineConfig(
  withSidebar(
    { title: 'My Docs' },
    {
      documentRootPath: '/docs',
      useTitleFromFileHeading: true,
      useFolderTitleFromIndexFile: true,
      removePrefixAfterOrdering: true,
      manualSortFileNameByPriority: ['introduction.md', 'guide']
    }
  )
);

3Your sidebar

Show the generated themeConfig.sidebar value
json
[
  { "text": "Introduction", "link": "/introduction" },
  {
    "text": "Guide",
    "items": [
      { "text": "Installation", "link": "/guide/1.installation" },
      { "text": "Configuration", "link": "/guide/2.configuration" },
      { "text": "Deployment", "link": "/guide/3.deployment" }
    ]
  },
  {
    "text": "API Reference",
    "items": [
      { "text": "Client Methods", "link": "/api/client-methods" },
      { "text": "Server Hooks", "link": "/api/server-hooks" }
    ]
  }
]
  • Menu titles come from the first heading of each page (useTitleFromFileHeading), and group titles from the index.md of each folder (useFolderTitleFromIndexFile).
  • The 1., 2., and 3. prefixes decide the order inside guide and are then removed from the titles (removePrefixAfterOrdering).
  • introduction.md and guide are placed first, and everything else follows by name (manualSortFileNameByPriority).
  • The home page index.md is left out of the menu, which is the default (includeRootIndexFile).

Use cases

Made for real documentation sites

Product manuals, multilingual sites, blogs, and generated reference pages all run on the same plugin, each with a few options.

A separate sidebar for each section

Give /guide/ and /api/ a sidebar of their own, so readers only see the menu of the section they are in.

js
withSidebar(vitePressOptions, [
  {
    documentRootPath: '/docs',
    scanStartPath: 'guide',
    resolvePath: '/guide/'
  },
  {
    documentRootPath: '/docs',
    scanStartPath: 'api',
    resolvePath: '/api/'
  }
]);

Read the multiple sidebars guide

Documentation in several languages

Generate one sidebar per language directory. Each translation gets a menu built from its own files and its own headings.

js
withSidebar(
  vitePressOptions,
  ['en', 'ko'].map((lang) => ({
    documentRootPath: `/docs/${lang}`,
    resolvePath: `/${lang}/`,
    useTitleFromFileHeading: true
  }))
);

Read the internationalization guide

A blog or release notes, newest first

Give each post a date in its frontmatter. The newest post stays at the top of the menu as you publish, with no list to maintain.

js
const sidebarOptions = {
  sortMenusByFrontmatterDate: true,
  sortMenusOrderByDescending: true
};

See every sorting option

Different rules for each part of the tree

A sidebar.config.json configures its folder and everything below it. Its $folder key names and links the folder itself, even without an index.md.

json
// docs/api/sidebar.config.json
{
  "collapsed": true,
  "$folder": {
    "text": "API Reference",
    "link": "/api/overview"
  }
}

Read the configuration file guide

Drafts that stay out of the menu

Mark an unfinished page with draft: true in its frontmatter and it is left out of the sidebar. Pages excluded by srcExclude are left out as well.

js
const sidebarOptions = {
  excludeFilesByFrontmatterFieldName: 'draft'
};

See every exclusion option

Pages generated by dynamic routes

A [pkg].md template and its paths loader appear as the pages they generate, one menu item per package, instead of as a template that links nowhere.

js
const sidebarOptions = {
  includeDynamicRoutes: true,
  useTitleFromFileHeading: true
};

Get started

Set up in three steps

VitePress Sidebar runs on Node.js 20 or later and works with the VitePress project you already have.

  1. Install the package

    Add it as a development dependency. It only runs while the site is built or served.

    sh
    npm i -D vitepress-sidebar
    sh
    yarn add -D vitepress-sidebar
    sh
    pnpm i -D vitepress-sidebar

  2. Wrap your VitePress config

    Pass your existing options to withSidebar together with the folder that holds your documents.

    js
    // docs/.vitepress/config.js
import { defineConfig } from 'vitepress';
import { withSidebar } from 'vitepress-sidebar';

const vitePressOptions = {
  title: 'My Docs'
};

export default defineConfig(
  withSidebar(vitePressOptions, {
    documentRootPath: '/docs'
  })
);

  3. Write Markdown

    Add, remove, or rename pages as usual. The page below appears under Guide as Upgrading. The sidebar is rebuilt on every build, and the dev server refreshes it when a page is added or removed.

    md
    <!-- docs/guide/4.upgrading.md -->

# Upgrading

Steps for moving to the next major version.

FAQ

Frequently asked questions

Does it replace a sidebar I already wrote?

Yes. withSidebar replaces themeConfig.sidebar with the generated sidebar. When some pages must stay in a fixed order, list them in manualSortFileNameByPriority or give them an order in their frontmatter instead of keeping a handwritten list.

How do I control the order of the menu?

Files and folders are sorted by name by default. You can put chosen names first, sort by the frontmatter order or date, sort by the numbers in titles or links, or decide every comparison yourself with sortMenusByCustomFunction.

Does the sidebar update while the dev server is running?

With withSidebar, adding or removing a Markdown file, or editing a sidebar.config.json, refreshes the sidebar without a manual restart. With generateSidebar, the dev server has to be restarted.

Can I use it in a CommonJS project?

The package is published as an ES module. Rename the VitePress config file to .mjs, or add "type": "module" to package.json. The troubleshooting page walks through both.

What does it require?

Node.js 20 or later, with Node.js 22 recommended, and a VitePress project. The getting started guide covers the installation.

Is it free to use?

Yes. VitePress Sidebar is open source under the MIT License, including in commercial projects. The source code and the issue tracker are on GitHub.
